1. NO. OF TABLES IN YOUR PROJECT
--------------------------------------------------------------------------------
Answer: 5 Main Tables (Plus 1 Migration History Table = 6 Total in SQL Database)

Entity Framework Core DbSets (ApplicationDbContext):
  1. Users
     - Purpose: Stores devotee and administrator account details, credentials, and roles.
     - Key Columns: UserId (PK), Name, Username, Email, Password, Role.

  2. Services
     - Purpose: Stores the catalog of authentic Vedic ceremonies and pujas.
     - Key Columns: ServiceId (PK), ServiceName, Description, Price, Duration, IsActive.

  3. Pandits
     - Purpose: Stores verified Gurukul Vedic Acharyas and Purohits.
     - Key Columns: PanditId (PK), Name, Mobile, Specialization, ExperienceYears, IsAvailable.

  4. TimeSlots
     - Purpose: Stores scheduled Muhurat timings allocated to Pandits.
     - Key Columns: SlotId (PK), PanditId (FK), Date, StartTime, EndTime, IsBooked.

  5. Bookings
     - Purpose: Stores devotee ceremony reservations, schedule, venue, dakshina, and status.
     - Key Columns: BookingId (PK), UserId (FK), PanditId (FK), ServiceId (FK), 
                    SlotId (FK), BookingDate, Address, TotalAmount, Status, 
                    PaymentMethod, CreatedAt.

  * Additional Internal Table:
    - __EFMigrationsHistory (tracks applied Entity Framework database migrations).

5. IS LOGIN PASSWORD IDENTITY FEATURES INCLUDED ?
--------------------------------------------------------------------------------
Answer: YES, Custom Role-Based Identity & High-Security Password Features are Fully Included.

Key Identity & Security Features:
  - Custom Database Identity:
    Managed via the Users table with distinct role claims ("Admin" vs "User").
  
  - Dual-Role Authentication:
    * Devotees sign in using their unique Username and Password.
    * Administrators sign in using their registered Email (admin@gmail.com) and Password.
    * Cross-role protection prevents standard devotees from accessing admin interfaces.

  - Strict Password Complexity Rules (Enforced Client-Side & Server-Side):
    1. Minimum 8 characters in length.
    2. At least one uppercase capital letter (A-Z).
    3. At least one lowercase letter (a-z).
    4. At least one numeric digit (0-9).
    5. At least one special symbol (@$!%*?&#^()_-+=).

  - Live Interactive Password Checklist:
    Displayed in real time on registration and admin password reset modals, turning
    green item-by-item as the user types.

  - Admin Password Visibility & Management:
    * Master toggle button: "Show All Passwords" / "Hide All Passwords" in Admin directory.
    * Individual row toggle: "Show / Hide" for each devotee row.
    * Admin Password Reset Modal: View current password and set a new compliant password.
    * "Auto-Generate Strong" Button: Instantly generates pre-validated passwords (e.g. Shubh@2026).

  - Session-Based Identity State:
    Stores UserId, UserName, UserEmail, and UserRole in encrypted HTTP-only session cookies
    with anti-cache headers preventing back-button browser cache leaks.


6. LINQ USED IN YOUR PROJECT ?
--------------------------------------------------------------------------------
Answer: YES, LINQ (Language Integrated Query) is Extensively Used Throughout the Project.

Over 135+ LINQ queries are used across the codebase for querying, filtering,
sorting, and aggregating database data through Entity Framework Core.

Examples of LINQ Methods Used:
  - .Where(...)
    Filtering active services, available pandits, unbooked Muhurat slots, and
    user-specific bookings:
    Example: _context.Services.Where(s => s.IsActive).ToList();

  - .FirstOrDefault(...) / .Find(...)
    Retrieving specific records for authentication, details, and edits:
    Example: _context.Users.FirstOrDefault(u => u.Username == username && u.Password == password);

  - .Include(...)
    Eager loading relational tables for complete booking and invoice details:
    Example: _context.Bookings.Include(b => b.User)
                              .Include(b => b.Service)
                              .Include(b => b.Pandit)
                              .Include(b => b.TimeSlot)
                              .FirstOrDefault(b => b.BookingId == id);

  - .Select(...)
    Projecting lightweight objects for live autocomplete search suggestions:
    Example: _context.Services.Where(...).Select(s => new { s.ServiceId, s.ServiceName, s.Price });

  - .OrderBy(...) / .OrderByDescending(...)
    Sorting booking histories in reverse chronological order and ordering Muhurat slots.

  - .Any(...)
    Checking if a username, email, or time slot conflict already exists.

  - .Count(...) & .Sum(...)
    Calculating admin dashboard KPI cards (Total Bookings, Confirmed Bookings, Total Dakshina).


7. SHOPPING CART DEVELOPED IN YOUR PROJECT ?
--------------------------------------------------------------------------------
Answer: NO Traditional E-Commerce Shopping Cart.
        INSTEAD, a Dedicated "Spiritual Ceremony Booking & Consecration Reservation System"
        is Developed.

Why Not a Standard E-Commerce Shopping Cart?
  - Vedic rituals, Havans, and Pujas are not physical consumer products that are added
    in multiples to an e-commerce shopping bag and delivered via courier.
  - Each sacred ceremony is a personalized spiritual sankalp requiring:
      1. A specific devotee (Yajman).
      2. An auspicious ceremony date (calculated via Vedic Panchang).
      3. A qualified Gurukul Pandit assigned exclusively to that ritual.
      4. An auspicious Muhurat time slot (e.g., Brahma Muhurat, Abhijit Muhurat).
      5. A specific ceremony location (devotee's residence, office, or temple sanctum).

How the Direct Spiritual Booking Flow Works:
  1. Ceremony Discovery:
     Devotee browses the catalog (/Service) or searches via the live autocomplete bar.
  2. Direct Sacred Booking (/Booking/Create?serviceId=X):
     Devotee selects the ceremony, picks the ceremony date via an interactive date picker,
     chooses an auspicious Muhurat slot, selects their preferred Pandit, and enters the address.
  3. Culturally Reverent Dakshina Offering:
     Devotee chooses their payment method:
       - UPI with dynamic QR code
       - Debit / Credit Card
       - "Pay Dakshina After Puja (In-Person)" (respectful alternative to awkward COD)
  4. Instant Consecration & Invoice:
     Devotee receives an immediate booking confirmation, a digital Sankalp Patra receipt,
     and a downloadable / printable single-page Sacred Dakshina PDF Invoice.
